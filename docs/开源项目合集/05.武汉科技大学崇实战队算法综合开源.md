# 武汉科技大学崇实战队算法综合开源

## 项目概览

武汉科技大学 RoboMaster 崇实战队公开了视觉、导航和决策相关项目：

| 项目 | 内容 | 主要环境 | 许可证 |
|---|---|---|---|
| [WUST-RM/awakening](https://github.com/WUST-RM/awakening) | 自动瞄准、能量机关、全向感知、雷达识别、哨兵决策 | C++23、OpenCV、OpenVINO/TensorRT；ROS 2 可选 | MIT |
| [hyheiyue/rose_navigation](https://github.com/hyheiyue/rose_navigation) | LiDAR-Inertial 定位、地图、A*、轨迹优化和 MPC | Ubuntu 22.04、ROS 2 Humble、C++20 | MIT |

综合介绍见 [RM2026 算法综合开源帖](https://bbs.robomaster.com/article/1936030?source=8)。项目仍在持续开发和优化中，接口与文档可能变化。

## 1. awakening：视觉与决策框架

### 功能范围

`awakening` 将算法模块与运行入口分离，覆盖：

- 自动瞄准；
- 能量机关；
- 全向感知；
- 雷达识别、定位和跟踪；
- 哨兵决策；
- 相机、串口、视频和点云 IO；
- SSH + Web 远程控制与可视化。

推理后端支持 OpenVINO 与 TensorRT/CUDA，可以按 NUC、Orin 和相机型号选择相应部署方式。ROS 2 主要用于通信和可视化，并不是所有运行入口的强制依赖。

### 仓库披露的运行时数据

README 以自动瞄准链路为例，统计从获取图像到该帧完成识别与状态估计的时间，并给出：

| 硬件 | 最大吞吐量 | 平均端到端时间 |
|---|---:|---:|
| Intel NUC 1240P + Hik CS016-10UC | 250 Hz，受相机帧率限制 | 6–8 ms |
| NVIDIA Orin NX 8G + Hik CS016-10UC | 250 Hz，受相机帧率限制 | 2–6 ms |

以上数据使用仓库指定模型和设备配置，由项目团队提供。不同模型、图像分辨率、相机 SDK、功耗模式和并发负载下需要重新测量。

### 构建入口

仓库依赖 CMake、Ninja、OpenCV、fmt、Ceres、Eigen3、yaml-cpp、TBB、Boost 等，并按硬件选装 OpenVINO、TensorRT/CUDA 和相机 SDK。

```bash
git clone --recurse-submodules https://github.com/WUST-RM/awakening.git
cd awakening
sudo ./run.sh build
sudo ./run.sh run standard omni true
```

算法文档包括整车状态估计、轨迹优化、图像识别和并发推理，具体见仓库 [README](https://github.com/WUST-RM/awakening#readme) 与 `docs/algorithm/`。

## 2. rose_navigation：轻量导航系统

`rose_navigation` 是面向小型高速地面平台和 RoboMaster 哨兵的 ROS 2 导航框架，提供从 LiDAR/IMU 输入到 `/cmd_vel` 的完整链路。

### 核心模块

| 模块 | 节点 | 作用 |
|---|---|---|
| LiDAR-Inertial 定位 | `rose_navigation_lm_node` | 输出里程计、配准点云和调试 Marker |
| 地图构建 | `rose_navigation_map_node` | 维护局部占据地图、二值地形地图和 ESDF |
| 规划控制 | `rose_navigation_planner_node` | A* 搜索、轨迹优化和 MPC，输出 `/cmd_vel` |

定位模块深度参考 [small_point_lio](https://github.com/Yancey2023/small_point_lio)，地图模块参考 [ROG-Map](https://github.com/hku-mars/ROG-Map)，规划与轨迹优化参考 [DDR-opt](https://github.com/ZJU-FAST-Lab/DDR-opt)。

### 数据链路

```text
LiDAR + IMU
     │
     ▼
LiDAR-Inertial 定位
     ├── /Odometry
     └── /cloud_registered
              │
              ▼
占据地图 + 二值地图 + ESDF
              │
目标点 ───────┤
              ▼
A* + 轨迹优化 + MPC
              │
              ▼
          /cmd_vel
```

项目没有以完整 Nav2 导航栈作为规划控制主体，但仍使用 `nav2_msgs` 等 ROS 2 消息依赖。迁移时应区分“没有采用 Nav2 完整行为树/规划控制框架”和“完全不安装任何 Nav2 相关消息包”这两个概念。

### 环境与启动

推荐环境为 Ubuntu 22.04、ROS 2 Humble、C++20，并依赖 Eigen3、OpenCV、yaml-cpp、TBB、OSQP 和 OsqpEigen。

```bash
ros2 launch rose_navigation mid360_lm.launch.py
ros2 launch rose_navigation rose_map.launch.py
ros2 launch rose_navigation rose_planner.launch.py
```

部署前需要根据实车调整 LiDAR/IMU 外参、雷达类型、局部地图尺寸、机器人半径、安全距离、最大速度/加速度和 MPC 权重。

## 适用边界

- 两个仓库都处于持续开发阶段，应固定经过验证的 commit 后再用于比赛版本。
- `awakening` 的性能数据不能直接外推到不同相机、模型和计算平台。
- `rose_navigation` 的定位、地形地图和 MPC 参数需要结合实际传感器与底盘重新配置。
- 视觉、导航和决策模块之间的消息接口、时间戳和坐标系仍需由使用团队统一设计和验证。
- 上游参考项目和随仓库使用的模型、SDK 可能采用不同许可证，集成前应逐项检查。

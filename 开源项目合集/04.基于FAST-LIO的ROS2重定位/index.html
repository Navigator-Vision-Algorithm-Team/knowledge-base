基于 FAST-LIO 的 ROS 2 重定位

项目概览

项目 内容
仓库 handshow888/fast_lio_based_localization
团队 东北大学秦皇岛分校征龙凌沧战队
定位思路 FAST-LIO 高频局部里程计 + NDT 低频先验地图配准
地图 PCD 点云地图
主要修正量 map 到里程计坐标系的变换
许可证 仓库当前未声明有效许可证

该仓库是对 BruceXSK/fast_lio_localization 的 ROS 2 迁移和工程化调整，维护者并非原始算法作者。原算法、FAST-LIO 和 NDT 相关代码的版权与成果归相应原作者所有。

工作原理

FAST-LIO 继续作为高频局部定位器，输出里程计和雷达本体坐标系下的配准点云。重定位节点根据运动阈值低频触发 NDT，将当前观测与先验 PCD 地图对齐，并持续修正全局地图坐标系与里程计坐标系之间的变换。

FAST-LIO 高频里程计与配准点云
                │
                ▼
运动量达到平移/旋转阈值
                │
                ▼
NDT 与先验 PCD 地图配准
                │
                ▼
更新 map → camera_init 变换
                │
                ▼
导航目标点与先验地图持续对齐

仓库中 camera_init 是 FAST-LIO 使用的里程计参考坐标系，可以理解为该实现中的 odom 语义坐标系。算法不直接修改 FAST-LIO 的底层状态，而是在更高层维护全局坐标变换。

主要输入

输入 类型或说明
/Odometry FAST-LIO 输出的 nav_msgs/msg/Odometry
/cloud_registered_body FAST-LIO 输出的 sensor_msgs/msg/PointCloud2
camera_init 里程计参考 TF 坐标系
map_path 先验 .pcd 点云地图的完整路径

配准参数包括初始位姿、平移/旋转触发阈值、线程数、最大迭代次数、体素大小、NDT 分辨率、步长以及点云距离范围等，具体以仓库 README 和配置文件为准。

适合解决的问题

  • 补偿机器人启动时人工摆放产生的全局初始位姿误差；
  • 修正局部里程计长时间运行产生的累计全局偏差；
  • 保持机器人在 map 坐标系中的位置与先验地图、导航目标点一致；
  • 在不侵入 FAST-LIO 内部估计器的情况下增加全局重定位能力。

理论上，该思路不局限于 FAST-LIO。只要其他 LiDAR-Inertial Odometry 能提供稳定的里程计、配准点云和清晰的坐标系关系，也可以进行适配，但需要重新处理消息接口和 TF 定义。

实车经验与限制

据开源者说明，这一 ROS 2 版本经过征龙凌沧战队连续多个赛季的实车使用，启动阶段能够较快完成重定位并收敛，长时间全图导航中没有观察到明显的全局定位漂移。对于包含人员走动拖影的先验地图，实际使用中仍有较高的重定位成功率。

上述内容属于战队实车经验，目前没有公开严谨的对比实验和定量测试，因此不应直接作为算法性能指标。

尤其要注意：

  1. 算法建立在底层里程计基本可靠的前提下，只负责修正全局位置偏差。
  2. 如果 LIO 已经严重发散、姿态跑飞或出现异常高度漂移，仅更新 map 到里程计坐标系的变换无法恢复底层状态。
  3. NDT 效果依赖先验地图质量、体素分辨率、初始位姿和当前观测的结构特征。
  4. 含动态拖影地图上的成功经验不能代替本队场景中的重复测试。
  5. 使用其他 LIO 时必须先明确其 odom、body、LiDAR 和 map 坐标系定义。

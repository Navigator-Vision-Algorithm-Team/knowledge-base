东北大学 TDT 战队哨兵导航前后端组件

资料整理与上传：朱鑫鹏

分类：规划前后端组件

项目概览

项目 内容
仓库 T-DT-Algorithm-2026/tdt-nav-kit
前端搜索 二维栅格 A、Kinodynamic A、代价场、多层障碍物掩码
后端优化 分段多项式、闭式/OSQP 求解、方形走廊、迭代碰撞处理
核心环境 C++11、Eigen3、OSQP、OsqpEigen，不依赖 ROS
示例环境 Ubuntu 22.04、GCC 11.2.0；OpenCV 仅用于示例可视化
许可证 MIT License

tdt-nav-kit 是东北大学 TDT 战队公开的哨兵导航前后端算法组件。它以二维栅格地图、起终点和运动约束为输入，完成代价地图生成、路径搜索、路径化简、约束区域生成和连续轨迹优化，可接入现有导航工程中从“收到导航目标”到“交给轨迹跟踪器”之间的链路。

项目不依赖 ROS，核心算法以 C++ 类和 Eigen 数据结构提供，适合已有定位、地图与控制框架，只希望替换或学习规划模块的队伍。项目介绍见 RoboMaster 社区开源帖。

该仓库不是完整的自主导航系统，未包含定位、建图、重定位、传感器驱动、全局任务管理和轨迹跟踪控制。集成者需要负责这些上下游模块，以及坐标系、地图更新、重规划触发和控制接口。

1. YAstar 前端搜索

YAstar 面向二维栅格地图，提供普通 A 和 Kinodynamic A 两种搜索方式。

普通 A*

普通 A* 使用八邻域扩展。除了基础占据地图，还可以依据障碍物距离生成代价场，让路径在长度和离障碍物的距离之间折中。多层位掩码可叠加临时障碍、禁行区等信息；基础地图或任意掩码层标记为障碍的栅格都会被排除。

搜索结果可以使用 DP 算法去除冗余点。仓库文档特别说明，单独调用 simplifyPath() 时不会结合地图检查化简后线段是否碰撞，因此集成时需要使用带碰撞检查的流程或自行补充验证。

Kinodynamic A*

Kinodynamic A* 将节点状态扩展为 [x, y, vx, vy]，使用加速度和持续时间进行状态转移，并过滤超过速度、加速度限制或发生碰撞的状态。接近终点时，可尝试用三次多项式连接终点并检查动力学约束与碰撞。

这种搜索比普通 A 更贴近车辆运动状态，但搜索空间明显增大。仓库文档建议长距离部分先使用 A 或 JPS 找到大致通路，再在车辆附近使用 Kinodynamic A*，避免让动力学搜索承担整条全局路径。

2. MinimumSnapOsqp 后端优化

后端使用分段多项式将离散路径转换为连续轨迹，支持闭式求解与 OSQP 二次规划求解。虽然模块名称为 MinimumSnapOsqp，仓库当前示例配置使用 0～5 阶多项式并最小化三阶导数，即 Minimum Jerk；导数阶数可通过参数调整。

方形约束与碰撞处理

项目借鉴安全飞行走廊的思路，在前端控制点附近扩张无碰撞方形区域，使优化后的轨迹不必严格经过原始控制点。轨迹求解后会按时间采样并检测碰撞；发生碰撞时，迭代加入控制点或缩短相应轨迹段的时间，再重新求解。

需要注意，仓库文档明确指出这里的方形区域不构成严格意义上的安全走廊：区域之间不一定相接，也不能从数学上保证整条多项式轨迹无碰撞。因此必须保留轨迹采样碰撞检查，并为迭代失败或超时准备拒绝执行和重新规划逻辑。

数值稳定性

每段轨迹可以使用 [0, 1] 的局部归一化时间表达，以减小不同轨迹段时长和高次幂造成的矩阵数量级差异。使用者仍应检查求解状态、轨迹系数是否为有限数，以及速度、加速度和碰撞约束是否实际满足。

示例参数与团队自测性能

仓库示例使用 0.05 m 栅格、4 层掩码、5 阶多项式、Minimum Jerk、0.1 s 采样间隔、6 次后端迭代、3.0 m/s 最大速度、1.0 m/s² 最大加速度和 OSQP 方形走廊后端。

团队在 AMD 7735H（4.2 GHz）、Ubuntu 22.04、GCC 11.2.0 环境中，每张地图执行 1000 次测试，README 报告的数据如下：

地图 阶段 平均时间 最大时间

RMUC 2024 Minimum Snap 1255.42 μs 14493.1 μs
RMUC 2024 生成代价地图 1604.13 μs 6870.61 μs
RMUC 2024 化简路径 34.0191 μs 242.632 μs

环境与运行示例

核心依赖为支持 C++11 的编译器、Eigen3、OSQP 和 OsqpEigen。仓库通过 Git 子模块固定 OSQP 与 OsqpEigen 版本，配置脚本会初始化并安装到 3rd/install：

git clone --recurse-submodules \
  https://github.com/T-DT-Algorithm-2026/tdt-nav-kit.git
cd tdt-nav-kit
./scripts/setup.sh

main.cpp 用于演示从读取地图到显示前端路径、方形区域和最终轨迹的流程。OpenCV 只服务于该示例的图像读取和可视化，不是核心算法组件的必要依赖。

mkdir build && cd build
cmake ..
make -j4
./play

建议按以下顺序阅读仓库文档：

  • Astar.md：普通 A、Kinodynamic A 与混合搜索思路；
  • MinimumSnap.md：多项式优化、方形约束、迭代碰撞处理和时间归一化；
  • Usage.md：类、参数、输入输出和调用示例。

集成检查清单

  1. 统一二维地图中“可行/障碍”的像素语义、地图分辨率、原点和坐标轴方向。
  2. 对真实坐标与栅格坐标的往返转换做边界测试，确保起终点不会越界或落入障碍。
  3. 将定位系统输出的当前速度正确传给规划器；不要把默认初速度 0.0 m/s 误认为强制静止起步。
  4. 根据机器人半径和定位误差对障碍物膨胀，不能把质点轨迹直接视为整车无碰撞。
  5. 对化简路径、走廊和最终采样轨迹分别执行碰撞检查。
  6. 检查求解失败、无路径、超时和地图更新时的返回状态，并在上层实现安全停车或重新规划。
  7. 在目标硬件上重新统计平均耗时、P95/P99 和最大耗时，再决定重规划频率。
  8. 将输出轨迹的时间、位置、速度和加速度约定与下游跟踪器对齐。
